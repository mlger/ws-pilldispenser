# Web Flasher

Status: Phase 0.5 placeholder site live; generated manifests arrive in Phase 6.

A static site deployed to GitHub Pages by `pages.yml`: it installs firmware on
the Waveshare ESP32-S3-Touch-LCD-4.3B from the browser via ESP Web Tools and
doubles as the download page for the Android APK and documentation.

## 1. Stack and pinning

ESP Web Tools is pinned at 10.4.0, loaded from a pinned CDN URL with
sub-resource integrity:

```html
<script
  type="module"
  src="https://unpkg.com/esp-web-tools@10.4.0/dist/web/install-button.js?module"
  integrity="sha384-f+fR3K1mnKB2tVps4hdEh+qJvLgH2bKw81Yn+eNE3+gE8YpqocjkxQON4k19I3e/"
  crossorigin="anonymous"
></script>
```

VERIFY: the SRI hash covers the entry module only; the bundle dynamically
imports sibling files, so sub-resource integrity for those files cannot be
expressed in a single script tag. Consider vendoring the full `dist/web`
directory in a later phase.

The page requires HTTPS (GitHub Pages provides it; enable "Enforce HTTPS"
when using a custom domain).

## 2. Same-origin binaries rule

All firmware binaries are copied INTO the Pages artifact and served from the
same origin; manifests never point at GitHub Release asset URLs. Same-origin
keeps the flasher self-contained and verifiable via `SHA256SUMS` inside the
artifact.

## 3. Manifest generation contract

- Input: `build/flasher_args.json` from the DEV build; output:
  `manifest.json` generated by `tools/flasher/gen_manifest.py`.
- Offsets are emitted in decimal; `chipFamily` is `"ESP32-S3"`.
- A contract test in `ci-web-flasher.yml` fails if any S3 manifest uses a
  bootloader offset other than `0` — the ESP32-S3 bootloader lives at `0x0`,
  never at `4096` (that value belongs to other ESP32 variants).
- `ota_data_initial.bin` is always included so the device boots into `ota_0`
  after a browser install.
- Manifests are never hand-written and never edited by hand; regenerate from
  the build.

Example shape (offsets illustrative; always generated in practice):

```json
{
  "name": "PillDispenser Main (dev channel)",
  "version": "1.4.0-dev.17+g3fa9c2e",
  "new_install_prompt_erase": true,
  "builds": [{
    "chipFamily": "ESP32-S3",
    "parts": [
      { "path": "bootloader.bin",       "offset": 0 },
      { "path": "partition-table.bin",  "offset": 32768 },
      { "path": "ota_data_initial.bin", "offset": 61440 },
      { "path": "pd-main.bin",          "offset": 65536 }
    ]
  }]
}
```

A sibling `release.json` (not inside the manifest) carries version, channel,
git SHA, build date, IDF version, SHA256 of every part and of the merged
`.bin`, and the changelog; the page renders these next to the button.

## 4. Install modes

| Mode | Mechanism | Use case |
| --- | --- | --- |
| Fresh install (erase) | `new_install_prompt_erase: true`; user confirms erase; NVS/LittleFS wiped | New device or "start over" |
| Update, keep settings | Parts mode: bootloader, partition table, otadata, app — never the merged image | Existing device, keep Wi-Fi and dose settings |

The merged image must never be used for updates: `merge_bin` pads the gaps
between parts with `0xFF`, so flashing it would overwrite NVS at `0x9000`
and destroy user settings.

## 5. Merged binary generation

Generated by `tools/flasher/merge_bin.sh` from the dev build:

```bash
cd firmware-main/build
python -m esptool --chip esp32s3 merge_bin -o pd-main-merged.bin @flash_args
```

esptool v5 spells the subcommand `merge-bin`; the script detects the version
and uses the right spelling. The merged `.bin` is offered as a download at
address `0x0`, matching Waveshare's own flashing procedure, for users of
esptool or the Espressif Flash Download Tool.

## 6. Channels and retention

| Channel | Content | Marking |
| --- | --- | --- |
| `stable/` | Latest non-prerelease Release (dev-config images) | default |
| `beta/` | Latest prerelease | beta |
| `dev/` | Last green `main` build | explicitly marked "development" |

- Keep the last 3 versions per channel to stay well under the 1 GB Pages
  limit; older versions link to their GitHub Releases.
- Production-hardened images (secure boot + flash encryption release mode)
  are NEVER offered on the page. Those devices update via signed OTA only:
  a browser flash of plaintext/unsigned images will fail to boot or be
  rejected, and release mode restricts download mode.

## 7. `pages.yml` deployment flow

1. `checkout` (permissions: `contents: read` for the build job).
2. Download the assets of the latest stable/beta release and the last green
   dev artifact, if any exist.
3. Run `tools/flasher/gen_manifest.py` and `tools/flasher/gen_release_json.py`.
4. Verify SHA256 of every binary against `SHA256SUMS`.
5. Build the site and upload it (`actions/configure-pages`,
   `actions/upload-pages-artifact`).
6. Deploy (`actions/deploy-pages`); the deploy job holds `pages: write` +
   `id-token: write`; environment: `github-pages`.

Pages source is set to "GitHub Actions". The deployment must finish within
the 10-minute budget; the job timeout enforces this.

## 8. Browser support

The page feature-detects `'serial' in navigator` and shows a banner.

| Browser | Status |
| --- | --- |
| Desktop Chrome / Edge 89+ | Supported |
| Opera | Supported |
| Firefox 151+ desktop | Supported (site-permission add-on prompt) |
| Chrome for Android 148+ | Best-effort (USB-OTG cable) |
| Safari (macOS/iOS) | Not supported |
| Firefox for Android | Not supported |

Unsupported browsers see the fallback instead of the install button: download
the merged `.bin` and flash it with esptool or the Espressif Flash Download
Tool at address `0x0`.

## 9. Putting the 4.3B into download mode

Verified against the Waveshare ESP32-S3-Touch-LCD-4.3B documentation:

1. Use the USB-C port labelled "UART" (it has the auto-download circuit) with
   a data-capable cable; close any open serial monitor first.
2. Click "Install" in the web flasher and pick the serial port.
3. If the port does not appear or the connection fails: unplug the board
   (and the 7-36 V supply/battery), hold BOOT, plug the USB cable in, release
   BOOT, then retry.
4. After flashing, press RESET — download mode is not exited automatically
   after a forced boot.
5. Linux: add your user to the `dialout` group. macOS: install the USB-UART
   driver if the port is missing.

## 11. Page contents

- Firmware install buttons for the three channels, with version, channel
  badge, SHA256 and changelog from `release.json`.
- Android APK download (from the Release) with its SHA256, plus a QR code to
  the Play / App Distribution link.
- Setup guide (`setup-guide.html`, rendered from `docs/setup-guide.md`) and a
  "check your firmware version" section.
- Privacy note: the page is static, collects no data, and never touches
  eFuses.
